Если честно — план выглядит рискованно, и у него есть несколько подводных камней, на которые часто натыкаются студенческие команды. Такой подход «эстафеты» (когда один делает всё, а потом передает другому) противоречит самой сути командной разработки, требования к которой жестко прописаны в вашем задании.  

Вот почему этот план стоит скорректировать и как сделать его намного эффективнее.
В чем главные минусы «последовательного» плана?

    Нарушение требований лабы: Преподаватель будет оценивать, как вы распределили задачи в GitHub Projects и как велась разработка. Если по коммитам и таскам будет видно, что сначала пахал один человек, а потом подключился второй, возникнут вопросы к командной работе.  

    Проблема «Автобуса» (Bus Factor): Ваш напарник половину проекта будет не в контексте. Когда придет его время кодить, ему придется потратить кучу времени просто на то, чтобы разобраться в вашем коде, архитектуре Jetpack Compose и структуре базы данных.  

    Потеря времени на CI/CD и тесты: Настройка GitHub Actions, UI-тестов (Espresso) и Firebase Test Lab — это огромный кусок работы. Если оставить это на самый конец, вы рискуете застрять на этапе сборки .apk в последнюю ночь перед сдачей.  

Как переиграть план: Параллельный подход

Гораздо круче и безопаснее разбить работу так, чтобы оба участника стартовали одновременно, но отвечали за разные изолированные модули приложения. Благо, современная Android-разработка это позволяет.

Вот отличный вариант разделения обязанностей для команды из двух человек:
Участник 1 (Тимлид / Разработчик UI и Логики)

    Задачи на старте: Создает организацию на GitHub и настраивает проект в GitHub Projects.  

    Разработка: * Проектирует структуру приложения (Activity/Фрагменты).  

        Верстает экраны на Jetpack Compose.  

        Реализует логику взаимодействия с внешними API (сетевые запросы).  

    Документация: Описывает функциональные требования и Use Case диаграммы в wiki.  

Участник 2 (Инженер данных / DevOps-инженер)

    Разработка: * Полностью берет на себя проектирование и создание базы данных (Room/SQLite). Пишет к ней DAO (интерфейсы для запросов) и сущности.  

        Реализует многопоточность для фоновых задач и локальные уведомления.  

    Автоматизация (CI/CD): Настраивает сценарии в GitHub Actions и интеграцию с Firebase Test Lab. Пишет Unit-тесты для проверки базы данных и бизнес-логики.  

    Документация: Создает схему базы данных (изображение + .sql файл) для wiki и настраивает репозиторий с документацией, добавляя код как submodule.  

Как вы будете взаимодействовать?

Вы синхронизируетесь на уровне архитектуры. Например, Участник 1 пишет интерфейс экрана профиля, а Участник 2 в это же время пишет код, который сохраняет данные этого профиля в базу данных. Вы создаете интерфейсы (Repository/API), договариваетесь, какими методами будете обмениваться данными, и спокойно работаете каждый в своей ветке (Git), не мешая друг другу.

Если разложить всё по полочкам, то проект состоит из трех огромных пластов работы. Вот что конкретно в них входит:  
1. Техническая обвязка самого приложения (Помимо UI)

Кроме верстки экранов на Jetpack Compose, в самом коде должны быть реализованы следующие архитектурные компоненты:  

    База данных: Нужно спроектировать таблицы, сущности (Entities) и написать DAO-интерфейсы (например, для Room). К ней же нужно приложить схему базы данных в виде картинки и .sql файла для документации.  

    Многопоточность (Асинхронность): Обработка «тяжелых» операций (запросы в БД, скачивание из сети) в фоновых потоках (корутины в Kotlin или потоки в Java/C++).  

    Сетевое взаимодействие: Написание логики для интеграции с внешними API (например, через Retrofit).  

    Элементы тач-интерфейса и уведомления: Обработка жестов/касаний и отправка локальных или push-уведомлений.  

2. Инфраструктура DevOps и Автоматизация (CI/CD)

Это важнейшая часть, которая проверяет ваши навыки как инженеров. Вам нужно настроить конвейер, который работает без вашего участия:

    Тестирование: * Unit-тесты: Проверка бизнес-логики и работы репозиториев/БД в изолированной среде.  

        UI-тесты: Автоматические тесты интерфейса (например, с помощью Espresso фреймворка), которые имитируют действия пользователя.  

    Firebase Test Lab: Интеграция с облачной лабораторией Google, где ваши UI-тесты будут автоматически прогоняться на реальных удаленных устройствах или эмуляторах.  

    GitHub Actions: Сценарий автоматизации (CI workflow). При каждом пуше в ветку он должен:  

        Подтягивать свежий код.

        Запускать Unit-тесты.  

        Отправлять приложение в Firebase Test Lab для UI-тестирования.  

        В случае успеха — автоматически собирать готовый .apk файл приложения и сохранять его как артефакт сборки.  

3. Менеджмент и Документация (3 площадки)

Документы пишутся на Markdown и публикуются параллельно на трех ресурсах:  

    Файл README.md в корне репозитория: Название, описание (3–5 предложений), гайд по установке, гайд по использованию (со скриншотами) и блок Contributing (кто из вас двоих что конкретно делал).  

    GitHub Wiki & GitHub Pages:

        Главная страница: Описание задачи и навигация.  

        Функциональные требования: Текстовые сценарии использования и Use Case диаграммы.  

        Диаграмма файлов: Схема структуры папок и классов проекта с описанием, что где лежит.  

        Схема БД: Картинка-схема отношений таблиц + ссылка на .sql файл.  

        Дополнительная спецификация: Документ с описанием ограничений проекта, требований к безопасности и надежности.  

    Управление (GitHub Projects): Интерактивная доска (Канбан), где заведены задачи, проставлены дедлайны и видно, на ком висит та или иная фича.  

    Презентация: Итоговый файл со структурой команды, архитектурой, схемой БД и описанием процесса работы.

Что делает напарник, когда подключается (Разработчик «Инфраструктуры»)

Через два дня ваш партнер приходит на готовую визуальную структуру. Он скачивает проект и сразу видит, какие сущности и экраны вы создали.

    Интеграция БД (Room/SQLite):

        Он смотрит на ваши экраны (например, экран «Профиль» или «Список задач») и понимает, какие таблицы нужны в базе данных.  

        Пишет сущности (Entities) и DAO-интерфейсы. Затем заменяет ваши «заглушки» на экранах на реальные вызовы из БД.  

    Параллельная настройка DevOps (GitHub Actions):

        Ему не нужно трогать ваш UI-код. Он может параллельно настраивать файл .github/workflows/main.yml для сборки .apk и интеграции с Firebase Test Lab.  

    Написание тестов:

        Пишет Unit-тесты для той базы данных, которую сам же и создал.  

Почему это сработает?

Вы будете работать в разных Git-ветках (например, вы в feature/ui-screens, он в feature/database-setup).
Поскольку вы разделили архитектурные слои (вы отвечаете за отображение, он — за хранение данных и автоматизацию), вы не будете перезаписывать код друг друга, и у вас не возникнет кошмарных merge-конфликтов в Git, когда он подключится.

    Для кого: Идеально для демонстрации работы с локальными уведомлениями (например, «Пора на тренировку!») и сложной бизнес-логики.

    Многопоточность и тач-интерфейс: Плавный свайп для удаления продуктов из списка покупок (Swipe-to-dismiss), фоновая загрузка картинок блюд и кэширование данных.

    Как работает сеть (API): Загрузка актуальных курсов валют или акций в реальном времени через бесплатные API (например, ExchangeRate-API).

    Как работает база данных (БД): Хранение категорий расходов/доходов, истории транзакций, лимитов на месяц и кошельков в разных валютах.

    Многопоточность и тач-интерфейс: Интерактивные графики расходов (pie-charts), реагирующие на касания. Фоновые потоки пересчитывают баланс во всех валютах при изменении курсов.

4. Агрегатор погоды и планировщик путешествий (Weather & Trip Planner)

Тема, в которой легко сделать красивый, динамичный интерфейс на Jetpack Compose.

    Как работает база данных (БД): Список избранных городов, сохраненные карточки планов для путешествий (какие места посетить, что взять с собой в зависимости от погоды).

Я создал репозиторий, а как моему партнеру подключиться в него?

Чтобы ваш партнёр получил полный доступ к репозиторию и доске проектов, вам нужно добавить его в вашу организацию team-weather. В GitHub это делается очень просто через приглашения.

Вот пошаговый алгоритм, как это сделать:
Шаг 1. Приглашение в организацию

    Зайдите на главную страницу вашей организации на GitHub (адрес будет вида github.com/team-weather).

    В верхнем меню выберите вкладку People (Пользователи).

    Введите GitHub-логин (username) вашего партнёра или его email и нажмите Invite.

    Назначьте ему роль Member (Участник) или Owner (Владелец, если хотите, чтобы у него были абсолютно те же права на управление организацией, что и у вас).

Шаг 2. Что должен сделать ваш партнёр

    Ему на почту придёт письмо со ссылкой-приглашением. Также он может просто зайти на страницу github.com/team-weather под своим аккаунтом.

    Он должен нажать кнопку Accept invitation (Принять приглашение).

Шаг 3. Проверка доступа к репозиторию

По умолчанию, когда вы приглашаете человека в организацию как Member, у него автоматически появляется доступ к публичным репозиториям. Но чтобы он мог спокойно пушить код в ветки, лучше проверить права:

    Зайдите в сам репозиторий с кодом внутри организации.

    Перейдите в Settings (Настройки репозитория) -> Collaborators and teams (или Manage access).

    Убедитесь, что у вашей команды или конкретно у вашего партнёра стоит уровень доступа Write (Запись) или Admin (Администрирование).

После этого ваш напарник сможет склонировать репозиторий себе на компьютер через Android Studio (Git -> Clone) и полноценно перемещать карточки на доске GitHub Projects.

А какую роль выбрать для партнера?

read

triage

Для вашего партнёра лучше всего выбрать роль write (Запись).

Вот почему это идеальный выбор и чем отличаются остальные роли:

    write (Оптимально): Дает вашему напарнику полную свободу действий с кодом. Он сможет создавать свои ветки, пушить туда код, делать коммиты, создавать и одобрять Pull Request'ы, а также полноценно управлять карточками задач на доске GitHub Projects. При этом он случайно не удалит сам репозиторий и не изменит глобальные настройки безопасности.

    maintain или admin: Эти роли дают слишком много административных прав (вплоть до удаления репозитория, изменения настроек интеграций и управления доступами других людей). Для совместной разработки кода это избыточно.

    read или triage: С этими ролями он просто не сможет отправить свой код в репозиторий. Роль read позволяет только скачивать код (как обычному зрителю), а triage — только управлять багами и задачами, но не кодить.

Итог: Выбирайте write — с ней ваш коллега сможет делать абсолютно всё, что требуется для выполнения проекта.

А если я дам admin мы оба будем admin?

Да, именно так! Если вы назначите ему роль admin, то вы оба станете администраторами этого репозитория с абсолютно одинаковыми, максимальными правами.

В условиях студенческого проекта дать напарнику admin — это вполне нормальная и частая практика, чтобы не отвлекаться на настройку доступов. Однако вам стоит учесть пару моментов:

    Полный контроль: Ваш партнёр сможет менять любые настройки репозитория, подключать сторонние сервисы, удалять ветки (даже главную) и, теоретически, удалить сам репозиторий. Если вы полностью доверяете напарнику и уверены, что он случайно ничего не сломает в настройках, можно смело ставить admin.

    Доступ к GitHub Actions и секретам: Для настройки DevOps (GitHub Actions + Firebase Test Lab) административный доступ может сильно облегчить ему жизнь, так как для интеграции с Firebase ему понадобится добавлять секретные ключи (Secrets) в настройки репозитория. С ролью write это делать сложнее, а с admin он настроит всё без вашей помощи.

Резюме: Если хотите подстраховаться от случайных изменений в настройках — ставьте write. Если хотите, чтобы у напарника вообще не возникало проблем с правами при настройке автосборок и тестов — ставьте admin.

Вот как это сделать по шагам прямо сейчас:
Шаг 1. Подготовка

У вас должно быть два репозитория:

    Репозиторий документации (тот, что в организации курса). Допустим, его адрес: https://github.com/fpmi-pmvs2026/team-weather.git.

Шаг 2. Клонирование репозитория документации

Bash

git clone https://github.com/fpmi-pmvs2026/team-weather.git

Шаг 3. Добавление подмодуля (кода)

Внутри папки репозитория документации выполните команду, которая добавит ваш личный репозиторий с кодом в качестве подмодуля:  
Bash

git submodule add https://github.com/ваш_логин/pmvs-weather-app.git app-code

(Здесь app-code — это название папки, которая создастся внутри документов и будет вести на ваш код ).  
Шаг 4. Фиксация изменений

Git создаст файл .gitmodules и зарегистрирует новую папку. Теперь нужно отправить эти настройки на GitHub:
Bash

git add .
git commit -m "Добавлен подмодуль для кода приложения"
git push origin main

Проект представляет собой интеллектуальный агрегатор погоды и планировщик путешествий, который помогает пользователям искать актуальные метеоданные для любых городов, локально сохранять списки будущих поездок, а также получать оперативные уведомления о неблагоприятных погодных условиях на основе данных из внешнего API. [cite_start]Приложение построено на базе современной архитектуры Android-разработки с использованием декларативного UI фреймворка Jetpack Compose, локального хранилища Room и автоматизированного CI/CD конвейера[cite: 10, 11, 12, 23].

Usage

Приложение обладает интуитивно понятным многооконным интерфейсом:  

    Главный экран (Погода): Введите название интересующего вас города в поисковую строку. Приложение выполнит асинхронный запрос к внешнему погодному API и отобразит текущую температуру, влажность и погодные условия.  

    Экран «Мои Поездки»: Перейдите на вкладку списка поездок, чтобы просмотреть запланированные путешествия, сохраненные в локальной базе данных Room.  

    Управление тач-интерфейсом: Используйте жест свайпа влево (Swipe-to-dismiss) на карточке поездки, чтобы быстро и плавно удалить её из списка.  

    Добавление поездки: Нажмите кнопку «Добавить», заполните простую форму (название, дата, город) и сохраните данные.

    Уведомления: Приложение автоматически проверяет метеоусловия для ваших запланированных мест назначения и присылает локальное push-уведомление, если в прогнозе ожидаются осадки или шторм.

Шаг 1. Добавляем библиотеку навигации (Navigation Compose)

В Jetpack Compose для перехода между экранами используется официальная библиотека navigation-compose. Её нужно прописать в файлах конфигурации Gradle.

    В Android Studio слева найди вкладку Project и разверни папку Gradle Scripts.

    Открой файл libs.versions.toml (это каталог зависимостей).

    В секцию [versions] добавь версию библиотеки:
    Ini, TOML

    androidx-navigation = "2.8.8"

    В секцию [libraries] добавь саму библиотеку:
    Ini, TOML

    androidx-navigation-compose = { group = "androidx.navigation", name = "navigation-compose", version.ref = "androidx-navigation" }

    Теперь открой файл build.gradle.kts (Module :app).

    В самый конец секции dependencies { ... } добавь строчку:
    Kotlin

    implementation(libs.androidx.navigation.compose)

    В правом верхнем углу Android Studio появится надпись Sync Now (Синхронизировать). Нажми её и подожди, пока Gradle подключит навигацию.

enum class Screen {
    WEATHER, TRIPS, ADD_TRIP
}

@Composable
fun AppNavigation() {
    val navController = rememberNavController()

    NavHost(
        navController = navController,
        startDestination = Screen.WEATHER.name // Стартовый экран
    ) {
        composable(route = Screen.WEATHER.name) {
            WeatherScreen(onNavigateToTrips = { navController.navigate(Screen.TRIPS.name) })

        composable(route = Screen.ADD_TRIP.name) {
            AddTripScreen(onBack = { navController.popBackStack() })
        }
    }

как поменять язык клавиатуры в эмуляторе?

Поменять язык ввода на клавиатуре внутри эмулятора Android Studio очень просто — это делается точно так же, как и на обычном физическом смартфоне.

Поскольку в эмуляторах по умолчанию стоит чистый Android, пройдите по следующему пути:
Инструкция (для Android 13 / 14):

    Внутри эмулятора зайдите в приложение Settings (Настройки — иконка шестерёнки).

    Прокрутите самый низ и выберите пункт System (Система).

    Нажмите на Languages & input (Язык и ввод).

    Выберите On-screen keyboard (Экранная клавиатура) -> Gboard (это стандартная клавиатура от Google).

    Нажмите на самый первый пункт — Languages (Языки).

    Внизу экрана нажмите кнопку Add keyboard (Добавить клавиатуру) и выберите из списка Russian (Русский).

    Нажмите Done (Готово).

Как теперь переключать язык при вводе?

    На экранной клавиатуре: Просто нажмите на иконку глобуса (рядом с пробелом) или зажмите сам пробел на секунду — откроется меню выбора языка.

    С клавиатуры компьютера (Hardware Keyboard): Если вы вводите текст в эмулятор физическими клавишами ноутбука/ПК, стандартная комбинация для переключения раскладки внутри Android — Ctrl + Пробел или Cmd + Пробел (для Mac).

Если переключение клавишами не работает, убедитесь, что в меню Settings -> System -> Languages & input -> Physical keyboard у вас стоит ползунок «Использовать экранную клавиатуру» или для физической клавиатуры тоже добавлены два языка (English и Русский).

как открыть настройки эмулятора через терминал android studio

Открыть именно графическое меню настроек (Settings) самого Android внутри эмулятора через терминал можно с помощью встроенного инструмента ADB (Android Debug Bridge).

В Android Studio терминал уже открыт в корне твоего проекта, поэтому тебе достаточно просто скопировать и выполнить специальную команду, которая отправляет эмулятору команду (Intent) на запуск настроек.

В зависимости от того, в какой именно раздел настроек тебе нужно попасть, выбери нужную команду:
1. Открыть главный экран настроек (Settings)

Эта команда откроет самый корень настроек (откуда можно перейти в раздел «Система» и поменять язык):
Bash

adb shell am start -a android.settings.SETTINGS

2. Сразу открыть настройки языков и ввода (Быстрый путь)

Чтобы не блуждать по меню, можно отправить команду, которая мгновенно перекинет тебя в настройки клавиатуры и языков:
Bash

adb shell am start -a android.settings.LOCALE_SETTINGS

или для настроек экранной клавиатуры:
Bash

adb shell am start -a android.settings.INPUT_METHOD_SETTINGS

💡 Что делать, если терминал пишет «adb: command not found»?

Это частая проблема, если пути к Android SDK не прописаны в системных переменных компьютера. Исправить это внутри Android Studio можно очень быстро, указав прямой путь к утилите.

    Если у тебя Windows:
    DOS

    %LOCALAPPDATA%\Android\Sdk\platform-tools\adb shell am start -a android.settings.SETTINGS

    Если у тебя macOS / Linux:
    Bash

    ~/Library/Android/sdk/platform-tools/adb shell am start -a android.settings.SETTINGS

После выполнения команды эмулятор прямо на твоих глазах переключится на нужный экран настроек!

package com.example.weathertripplanner.ui.screens

import androidx.compose.foundation.layout.*

import androidx.compose.foundation.lazy.items
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Add
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.unit.dp
import androidx.compose.ui.unit.sp

// Временная модель данных для отображения структуры поездки.
// В будущем Room будет использовать похожий класс, но с аннотацией @Entity
data class TripMock(val id: Int, val title: String, val city: String, val date: String)

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun TripsScreen(onNavigateToId: () -> Unit) {
    // mutableStateListOf позволяет Compose автоматически перерисовывать экран,
    // если из этого списка удаляется элемент или добавляется новый.
    val mockTrips = remember {
        mutableStateListOf(
            TripMock(1, "Поездка к бабушке", "Брест", "25.05.2026"),
            TripMock(2, "Выезд на шашлыки", "Заславль", "30.05.2026"),
            TripMock(3, "Летний отпуск", "Grodno", "15.07.2026")
        )
    }

    Scaffold(
        // Верхняя панель приложения с названием экрана
        topBar = {
            TopAppBar(
                title = { Text("Мои Поездки", fontWeight = FontWeight.Bold) }
            )
        },
        // Круглая плавающая кнопка "+" для перехода на экран добавления
        floatingActionButton = {
            FloatingActionButton(
                onClick = onNavigateToId,
                containerColor = MaterialTheme.colorScheme.primary
            ) {
                Icon(
                    imageVector = Icons.Default.Add, 
                    contentDescription = "Добавить поездку", 
                    tint = MaterialTheme.colorScheme.onPrimary
                )
            }
        }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding)
                .padding(horizontal = 16.dp)
        ) {
            // Проверяем: если список пустой (например, всё удалили), показываем заглушку
            if (mockTrips.isEmpty()) {
                Box(
                    modifier = Modifier.fillMaxSize(),
                    contentAlignment = Alignment.Center
                ) {
                    Text(
                        text = "У вас нет запланированных поездок", 
                        color = MaterialTheme.colorScheme.onSurfaceVariant
                    )
                }
            } else {
                // Оптимизированный список LazyColumn (аналог RecyclerView)
                LazyColumn(
                    verticalArrangement = Arrangement.spacedBy(12.dp),
                    modifier = Modifier.fillMaxSize()
                ) {
                    // Передаем список и ключ (key) для плавной анимации в будущем
                    items(items = mockTrips, key = { it.id }) { trip ->
                        TripCard(trip = trip)
                    }
                }
            }
        }
    }
}

// Компонент отдельной карточки поездки
@Composable
fun TripCard(trip: TripMock) {
    Card(
        modifier = Modifier.fillMaxWidth(),
        shape = RoundedCornerShape(16.dp),
        colors = CardDefaults.cardColors(
            containerColor = MaterialTheme.colorScheme.surfaceVariant
        )
    ) {
        Column(
            modifier = Modifier
                .fillMaxWidth()
                .padding(16.dp)
        ) {
            Text(
                text = trip.title,
                style = MaterialTheme.typography.titleMedium,
                fontWeight = FontWeight.Bold
            )
            Spacer(modifier = Modifier.height(8.dp))
            Row(
                modifier = Modifier.fillMaxWidth(),
                horizontalArrangement = Arrangement.SpaceBetween
            ) {
                Text(text = "📍 ${trip.city}", style = MaterialTheme.typography.bodyMedium)
                Text(
                    text = "📅 ${trip.date}", 
                    style = MaterialTheme.typography.bodyMedium, 
                    fontWeight = FontWeight.Medium
                )
            }
        }
    }
}

Kotlin

package com.example.weathertripplanner.ui.screens

import androidx.compose.foundation.layout.*
import androidx.compose.foundation.rememberScrollState
import androidx.compose.foundation.verticalScroll
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.automirrored.filled.ArrowBack
import androidx.compose.material.icons.filled.CalendarToday
import androidx.compose.material.icons.filled.CardTravel
import androidx.compose.material.icons.filled.Place
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.unit.dp

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun AddTripScreen(onBack: () -> Unit) {
    // Состояния для хранения текста, который вводит пользователь
    var title by remember { mutableStateOf("") }
    var city by remember { mutableStateOf("") }
    var date by remember { mutableStateOf("") }

    // Простая валидация: кнопка "Сохранить" будет активна, только если все поля заполнены
    val isFormValid = title.isNotBlank() && city.isNotBlank() && date.isNotBlank()

    Scaffold(
        topBar = {
            TopAppBar(
                title = { Text("Новая поездка", fontWeight = FontWeight.Bold) },
                // Кнопка "Назад" в левом верхнем углу
                navigationIcon = {
                    IconButton(onClick = onBack) {
                        Icon(
                            imageVector = Icons.AutoMirrored.Filled.ArrowBack,
                            contentDescription = "Назад"
                        )
                    }
                }
            )
        }
    ) { innerPadding ->
        // verticalScroll нужен на случай, если на маленьких экранах или при открытой клавиатуре вся форма не поместится
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding)
                .padding(16.dp)
                .verticalScroll(rememberScrollState()),
            verticalArrangement = Arrangement.spacedBy(16.dp)
        ) {
            // Поле ввода названия поездки
            OutlinedTextField(
                value = title,
                onValueChange = { title = it },
                label = { Text("Название поездки") },
                placeholder = { Text("Например: Отпуск у моря") },
                leadingIcon = { Icon(Icons.Default.CardTravel, contentDescription = null) },
                modifier = Modifier.fillMaxWidth(),
                singleLine = true
            )

            // Поле ввода города
            OutlinedTextField(
                value = city,
                onValueChange = { city = it },
                label = { Text("Город назначения") },
                placeholder = { Text("Например: Брест") },
                leadingIcon = { Icon(Icons.Default.Place, contentDescription = null) },
                modifier = Modifier.fillMaxWidth(),
                singleLine = true
            )

            // Поле ввода даты (пока текстовое, позже прикрутим календарь)
            OutlinedTextField(
                value = date,
                onValueChange = { date = it },
                label = { Text("Дата поездки") },
                placeholder = { Text("Например: 25.05.2026") },
                leadingIcon = { Icon(Icons.Default.CalendarToday, contentDescription = null) },
                modifier = Modifier.fillMaxWidth(),
                singleLine = true
            )

            Spacer(modifier = Modifier.height(16.dp))

            // Кнопка сохранения
            Button(
                onClick = {
                    // ТУТ в будущем будет запись в базу данных Room.
                    // А пока просто имитируем успешное сохранение и возвращаем пользователя назад.
                    onBack()
                },
                modifier = Modifier.fillMaxWidth(),
                enabled = isFormValid, // Кнопка блокируется, если форма пустая
                colors = ButtonDefaults.buttonColors(
                    containerColor = MaterialTheme.colorScheme.primary
                )
            ) {
                Text("Сохранить", style = MaterialTheme.typography.titleMedium)
            }
        }
    }
}

Дело в том, что система сборки Gradle работает как пылесос: когда ты добавляешь новые библиотеки (например, мы недавно добавили androidx.navigation), Gradle лезет на удаленные серверы (Google, MavenCentral), чтобы скачать сами библиотеки, их исходники и кучу сопутствующих файлов. Если в этот момент интернет нестабилен, провайдер режет скорость или лежат сами сервера репозиториев, Gradle будет бесконечно пытаться их выкачать.

Однако интернет — не единственный виновник. Вот ТОП-3 причин, почему Android Studio может долго собирать проект:
1. Первичная загрузка «на холодную» (Зависит от интернета)

Если ты только что добавил новую библиотеку, изменил файл build.gradle.kts или запустил проект после долгого перерыва, Gradle делает холодную сборку. Он качает всё заново.

    Как проверить: Посмотри в самый низ экрана Android Studio. Если там написано Downloading... или Indexing..., значит, он действительно качает файлы из сети. Следующие сборки будут идти в разы быстрее, так как файлы сохранятся на компьютере (в кэше).

2. Настройки самого Gradle (Зависит от конфигурации)

По умолчанию Android Studio выделяет Gradle очень скромный запас оперативной памяти. Из-за этого сборщик постоянно упирается в лимит и начинает тормозить.
3. Мощность железа

Компиляция Kotlin-кода и сборка Jetpack Compose — это ресурсоемкий процесс, который сильно нагружает процессор (CPU) и жесткий диск. Если проект лежит на обычном HDD, а не на быстром SSD, сборка всегда будет долгой.
🛠 Как ускорить сборку прямо сейчас?

Если интернет лагает, но все библиотеки ты уже хотя бы раз успешно скачивал, можно включить Offline Mode (Автономный режим). Gradle перестанет ходить в сеть и будет брать всё строго из кэша компьютера.

    В самом правом вертикальном меню Android Studio найди вкладку Gradle (слон).

    В открывшейся панели сверху найди иконку Toggle Offline Mode (выглядит как круглая планета со слэшем или кнопка с сигналом WiFi).

    Нажми её и попробуй запустить проект снова. Сборка пролетит моментально.

    ⚠️ Важно: если ты решишь добавить новую библиотеку, автономный режим нужно будет выключить обратно, иначе Gradle не сможет её скачать.

Это значит, что сейчас кнопка работает просто как улучшенная стрелка «Назад»: она проверяет, что ты всё заполнил, а при нажатии стирает экран из стека навигации и возвращает тебя на список поездок.

Шаг 4: Создаем DAO (Интерфейс запросов)

В папке data/database/ создай Kotlin-интерфейс TripDao.kt. Здесь мы описываем, какие действия хотим совершать с базой данных. Обрати внимание, что для получения списка мы используем Flow — это позволит интерфейсу автоматически обновляться, как только данные в таблице изменятся.
Kotlin

package com.example.weathertripplanner.data.database

import androidx.room.*
import com.example.weathertripplanner.data.model.TripEntity
import kotlinx.coroutines.flow.Flow

@Dao
interface TripDao {

    // Получить все поездки, сортируем по ID (новые будут внизу или вверху, как захочешь)
    @Query("SELECT * FROM trips ORDER BY id DESC")
    fun getAllTrips(): Flow<List<TripEntity>>

    // Добавить новую поездку. OnConflictStrategy.REPLACE обновит данные, если ID совпадет
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertTrip(trip: TripEntity)

    // Удалить конкретную поездку (пригодится для свайпа)
    @Delete
    suspend fun deleteTrip(trip: TripEntity)
}

Шаг 5: Создаем сам класс Базы Данных

В той же папке data/database/ создай абстрактный класс AppDatabase.kt. Он связывает таблицу и DAO воедино.
Kotlin

package com.example.weathertripplanner.data.database

import android.content.Context
import androidx.room.Database
import androidx.room.Room
import androidx.room.RoomDatabase
import com.example.weathertripplanner.data.model.TripEntity

@Database(entities = [TripEntity::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() {

    abstract fun tripDao(): TripDao

    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null

        // Синхронизированный синглтон, чтобы у приложения был только один экземпляр БД
        fun getDatabase(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                val instance = Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "weather_trip_database"
                ).build()
                INSTANCE = instance
                instance
            }
        }
    }
}

Давай создадим для бизнес-логики отдельную папку. Рядом с папками ui и data создай пакет (package) с именем viewmodel (или внутри ui, как тебе больше нравится, но на уровне корня — чище).

Kotlin

package com.example.weathertripplanner.viewmodel

import android.app.Application
import androidx.lifecycle.AndroidViewModel
import androidx.lifecycle.viewModelScope
import com.example.weathertripplanner.data.database.AppDatabase
import com.example.weathertripplanner.data.model.TripEntity
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.stateIn
import kotlinx.coroutines.launch

// Используем AndroidViewModel, так как нам нужен context для инициализации базы данных
class TripViewModel(application: Application) : AndroidViewModel(application) {

    // Получаем доступ к DAO нашей базы данных
    private val tripDao = AppDatabase.getDatabase(application).tripDao()

    // Превращаем Flow из Room в StateFlow, который Jetpack Compose умеет читать как состояние.
    // Благодаря этому интерфейс будет автоматически обновляться при любых изменениях в БД.
    val tripsState: StateFlow<List<TripEntity>> = tripDao.getAllTrips()
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )

    // Функция добавления поездки (запускается в асинхронном корутин-скоупе)
    fun addTrip(title: String, city: String, date: String) {
        viewModelScope.launch {
            val newTrip = TripEntity(title = title, city = city, date = date)
            tripDao.insertTrip(newTrip)
        }
    }

    // Функция удаления поездки (пригодится для свайпов)
    fun deleteTrip(trip: TripEntity) {
        viewModelScope.launch {
            tripDao.deleteTrip(trip)
        }
    }
}

Шаг 1: Передаем ViewModel в Навигацию

Открой файл app/src/main/java/com/example/weathertripplanner/ui/navigation/AppNavigation.kt.

Нам нужно инициализировать TripViewModel прямо здесь и передать его функции AppNavigation, а оттуда — прокинуть в экраны. Перепиши код файла следующим образом:
Kotlin

package com.example.weathertripplanner.ui.navigation

import androidx.compose.runtime.Composable
import androidx.lifecycle.viewmodel.compose.viewModel
import androidx.navigation.compose.NavHost
import androidx.navigation.compose.composable
import androidx.navigation.compose.rememberNavController
import com.example.weathertripplanner.ui.screens.AddTripScreen
import com.example.weathertripplanner.ui.screens.MainScreen
import com.example.weathertripplanner.ui.screens.TripsScreen
import com.example.weathertripplanner.viewmodel.TripViewModel

enum class Screen {
    MAIN,
    TRIPS,
    ADD_TRIP
}

@Composable
fun AppNavigation() {
    val navController = rememberNavController()
    
    // Инициализируем нашу ViewModel. Она будет одна на весь граф навигации.
    val tripViewModel: TripViewModel = viewModel()

    NavHost(
        navController = navController,
        startDestination = Screen.MAIN.name
    ) {
        composable(route = Screen.MAIN.name) {
            MainScreen(onNavigateToTrips = { navController.navigate(Screen.TRIPS.name) })
        }
        
        composable(route = Screen.TRIPS.name) {
            // Передаем ViewModel и действие для перехода на экран добавления
            TripsScreen(
                viewModel = tripViewModel,
                onNavigateToId = { navController.navigate(Screen.ADD_TRIP.name) }
            )
        }
        
        composable(route = Screen.ADD_TRIP.name) {
            // Передаем ViewModel и действие для возврата назад
            AddTripScreen(
                viewModel = tripViewModel,
                onBack = { navController.popBackStack() }
            )
        }
    }
}

package com.example.weathertripplanner.ui.screens

import androidx.compose.animation.animateColorAsState
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Add
import androidx.compose.material.icons.filled.Delete
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.unit.dp
import com.example.weathertripplanner.data.model.TripEntity
import com.example.weathertripplanner.viewmodel.TripViewModel

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun TripsScreen(
    viewModel: TripViewModel,
    onNavigateToId: () -> Unit,
    onBack: () -> Unit
) {
    val trips by viewModel.tripsState.collectAsState()

    Scaffold(
        topBar = {
            TopAppBar(
                title = { Text("Мои Поездки", fontWeight = FontWeight.Bold) },
                navigationIcon = {
                    IconButton(onClick = onBack) {
                        Icon(
                            imageVector = Icons.AutoMirrored.Filled.ArrowBack,
                            contentDescription = "Назад на экран погоды"
                        )
                    }
                }
            )
        },
        floatingActionButton = {
            FloatingActionButton(
                onClick = onNavigateToId,
                containerColor = MaterialTheme.colorScheme.primary
            ) {
                Icon(
                    imageVector = Icons.Default.Add,
                    contentDescription = "Добавить поездку",
                    tint = MaterialTheme.colorScheme.onPrimary
                )
            }
        }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding)
                .padding(horizontal = 16.dp)
        ) {
            if (trips.isEmpty()) {
                Box(
                    modifier = Modifier.fillMaxSize(),
                    contentAlignment = Alignment.Center
                ) {
                    Text(
                        text = "У вас нет запланированных поездок",
                        color = MaterialTheme.colorScheme.onSurfaceVariant
                    )
                }
            } else {
                LazyColumn(
                    verticalArrangement = Arrangement.spacedBy(12.dp),
                    modifier = Modifier.fillMaxSize()
                ) {
                    // Используем id в качестве ключа, чтобы Compose правильно анимировал удаление
                    items(items = trips, key = { it.id }) { trip ->
                        
                        // 1. Настраиваем состояние свайпа
                        val dismissState = rememberSwipeToDismissBoxState(
                            confirmValueChange = { newValue ->
                                if (newValue == SwipeToDismissBoxValue.EndToStart) {
                                    // Если свайпнули справа налево — удаляем из БД
                                    viewModel.deleteTrip(trip)
                                    true
                                } else {
                                    false
                                }
                            }
                        )

                        // 2. Сам контейнер свайпа
                        SwipeToDismissBox(
                            state = dismissState,
                            enableDismissFromStartToEnd = false, // Свайп слева направо отключен
                            enableDismissFromEndToStart = true,  // Свайп справа налево включен
                            backgroundContent = {
                                // Задний фон, который плавно краснеет при свайпе
                                val color by animateColorAsState(
                                    targetValue = when (dismissState.targetValue) {
                                        SwipeToDismissBoxValue.EndToStart -> Color.Red.copy(alpha = 0.8f)
                                        else -> Color.Transparent
                                    },
                                    label = "BackgroundColorAnimation"
                                )
                                
                                Box(
                                    modifier = Modifier
                                        .fillMaxSize()
                                        .background(color, shape = RoundedCornerShape(16.dp))
                                        .padding(horizontal = 20.dp),
                                    contentAlignment = Alignment.CenterEnd
                                ) {
                                    Icon(
                                        imageVector = Icons.Default.Delete,
                                        contentDescription = "Удалить",
                                        tint = Color.White
                                    )
                                }
                            },
                            content = {
                                // Передний план — наша старая добрая карточка
                                TripCard(trip = trip)
                            }
                        )
                    }
                }
            }
        }
    }
}

@Composable
fun TripCard(trip: TripEntity) {
    Card(
        modifier = Modifier.fillMaxWidth(),
        shape = RoundedCornerShape(16.dp),
        colors = CardDefaults.cardColors(
            containerColor = MaterialTheme.colorScheme.surfaceVariant
        )
    ) {
        Column(
            modifier = Modifier
                .fillMaxWidth()
                .padding(16.dp)
        ) {
            Text(
                text = trip.title,
                style = MaterialTheme.typography.titleMedium,
                fontWeight = FontWeight.Bold
            )
            Spacer(modifier = Modifier.height(8.dp))
            Row(
                modifier = Modifier.fillMaxWidth(),
                horizontalArrangement = Arrangement.SpaceBetween
            ) {
                Text(text = "📍 ${trip.city}", style = MaterialTheme.typography.bodyMedium)
                Text(
                    text = "📅 ${trip.date}",
                    style = MaterialTheme.typography.bodyMedium,
                    fontWeight = FontWeight.Medium
                )
            }
        }
    }
}

                    colors = OutlinedTextFieldDefaults.colors(
                        disabledTextColor = MaterialTheme.colorScheme.onSurface,
                        disabledBorderColor = MaterialTheme.colorScheme.outline,
                        disabledLeadingIconColor = MaterialTheme.colorScheme.onSurfaceVariant,
                        disabledLabelColor = MaterialTheme.colorScheme.onSurfaceVariant,
                        disabledPlaceholderColor = MaterialTheme.colorScheme.onSurfaceVariant,
                    )
                )
                // Невидимый слой поверх поля для перехвата клика
                Box(
                    modifier = Modifier
                        .matchParentSize()
                        .clickable { showDatePicker = true }
                )
            }

            Spacer(modifier = Modifier.height(16.dp))

            Button(
                onClick = {
                    viewModel.addTrip(title = title, city = city, date = dateText)
                    onBack()
                },
                modifier = Modifier.fillMaxWidth(),
                enabled = isFormValid
            ) {
                Text("Сохранить", style = MaterialTheme.typography.titleMedium)
            }
        }
        
        // Сам диалог календаря
        if (showDatePicker) {
            DatePickerDialog(
                onDismissRequest = { showDatePicker = false },
                confirmButton = {
                    TextButton(onClick = {
                        val selectedDate = datePickerState.selectedDateMillis
                        if (selectedDate != null) {
                            dateText = convertMillisToDate(selectedDate)
                        }
                        showDatePicker = false
                    }) {
                        Text("ОК")
                    }
                },
                dismissButton = {
                    TextButton(onClick = { showDatePicker = false }) {
                        Text("Отмена")
                    }
                }
            ) {
                DatePicker(state = datePickerState)
            }
        }
    }
}

// Вспомогательная функция для форматирования даты
fun convertMillisToDate(millis: Long): String {
    val formatter = SimpleDateFormat("dd.MM.yyyy", Locale.getDefault())
    return formatter.format(Date(millis))
}

package com.example.weathertripplanner.data.database

@Dao

package com.example.weathertripplanner.viewmodel

import android.app.Application
import androidx.lifecycle.AndroidViewModel
import androidx.lifecycle.viewModelScope
import com.example.weathertripplanner.data.database.AppDatabase
import com.example.weathertripplanner.data.model.TripEntity
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.stateIn
import kotlinx.coroutines.launch

class TripViewModel(application: Application) : AndroidViewModel(application) {

    private val tripDao = AppDatabase.getDatabase(application).tripDao()

    val tripsState: StateFlow<List<TripEntity>> = tripDao.getAllTrips()
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )

    fun addTrip(title: String, city: String, date: String) {
        viewModelScope.launch {
            val newTrip = TripEntity(title = title, city = city, date = date)
            tripDao.insertTrip(newTrip)
        }
    }

    fun deleteTrip(trip: TripEntity) {
        viewModelScope.launch {
            tripDao.deleteTrip(trip)
        }
    }

    suspend fun getTripById(id: Int): TripEntity? {
        return tripDao.getTripById(id)
    }
}

package com.example.weathertripplanner.ui.screens

import androidx.compose.animation.animateColorAsState

                    contentDescription = "Добавить поездку",
                    tint = MaterialTheme.colorScheme.onPrimary
                )
            }
        }
    ) { innerPadding ->

                .fillMaxSize()
                .padding(innerPadding)
                .padding(horizontal = 16.dp)

package com.example.weathertripplanner.ui.screens

import androidx.compose.foundation.clickable
import androidx.compose.foundation.layout.*

import androidx.compose.foundation.verticalScroll
import androidx.compose.material.icons.Icons

import androidx.compose.material.icons.filled.CardTravel
import androidx.compose.material.icons.filled.Place
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.unit.dp
import com.example.weathertripplanner.viewmodel.TripViewModel
import java.text.SimpleDateFormat
import java.util.*

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun AddTripScreen(
    viewModel: TripViewModel,
    onBack: () -> Unit
) {
    var title by remember { mutableStateOf("") }
    var city by remember { mutableStateOf("") }
    var dateText by remember { mutableStateOf("") }
    
    // Флаги: трогал ли пользователь поля (чтобы не пугать красным цветом сразу при старте)
    var isTitleTouched by remember { mutableStateOf(false) }
    var isCityTouched by remember { mutableStateOf(false) }
    var isDateTouched by remember { mutableStateOf(false) }

    // Условия ошибок (поле тронуто и оно пустое/в пробелах)
    val isTitleError = isTitleTouched && title.isBlank()
    val isCityError = isCityTouched && city.isBlank()
    val isDateError = isDateTouched && dateText.isBlank()

    // Кнопка активна только если ВСЕ поля заполнены корректно
    val isFormValid = title.isNotBlank() && city.isNotBlank() && dateText.isNotBlank()

    var showDatePicker by remember { mutableStateOf(false) }
    
    val datePickerState = rememberDatePickerState(
        selectableDates = object : SelectableDates {
            override fun isSelectableDate(utcTimeMillis: Long): Boolean {
                return utcTimeMillis >= System.currentTimeMillis() - 86400000
            }
        }
    )

    Scaffold(
        topBar = {
            TopAppBar(
                title = { Text("Новая поездка", fontWeight = FontWeight.Bold) },
                navigationIcon = {
                    IconButton(onClick = onBack) {
                        Icon(
                            imageVector = Icons.AutoMirrored.Filled.ArrowBack,
                            contentDescription = "Назад"
                        )
                    }
                }
            )
        }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding)
                .padding(16.dp)
                .verticalScroll(rememberScrollState()),
            verticalArrangement = Arrangement.spacedBy(16.dp)
        ) {
            
            // 1. Поле НАЗВАНИЕ с валидацией
            OutlinedTextField(
                value = title,
                onValueChange = { 
                    title = it
                    isTitleTouched = true // Фиксируем, что ввод начался
                },
                label = { Text("Название поездки") },
                leadingIcon = { Icon(Icons.Default.CardTravel, contentDescription = null) },
                modifier = Modifier.fillMaxWidth(),
                singleLine = true,
                isError = isTitleError, // Включаем красную рамку
                supportingText = {
                    if (isTitleError) {
                        Text("Название не может быть пустым", color = MaterialTheme.colorScheme.error)
                    }
                }
            )

            // 2. Поле ГОРОД с валидацией
            OutlinedTextField(
                value = city,
                onValueChange = { 
                    city = it
                    isCityTouched = true 
                },
                label = { Text("Город назначения") },
                leadingIcon = { Icon(Icons.Default.Place, contentDescription = null) },
                modifier = Modifier.fillMaxWidth(),
                singleLine = true,
                isError = isCityError, // Включаем красную рамку
                supportingText = {
                    if (isCityError) {
                        Text("Укажите город назначения", color = MaterialTheme.colorScheme.error)
                    }
                }
            )

            // 3. Поле ДАТЫ с валидацией
            Box {
                OutlinedTextField(
                    value = dateText,
                    onValueChange = { },
                    label = { Text("Дата поездки") },
                    leadingIcon = { Icon(Icons.Default.CalendarToday, contentDescription = null) },
                    modifier = Modifier.fillMaxWidth(),
                    readOnly = true,
                    enabled = false,
                    isError = isDateError, // Включаем красную рамку
                    supportingText = {
                        if (isDateError) {
                            Text("Выберите дату поездки", color = MaterialTheme.colorScheme.error)
                        }
                    },
                    colors = OutlinedTextFieldDefaults.colors(
                        disabledTextColor = if (isDateError) MaterialTheme.colorScheme.error else MaterialTheme.colorScheme.onSurface,
                        disabledBorderColor = if (isDateError) MaterialTheme.colorScheme.error else MaterialTheme.colorScheme.outline,
                        disabledLeadingIconColor = MaterialTheme.colorScheme.onSurfaceVariant,
                        disabledLabelColor = if (isDateError) MaterialTheme.colorScheme.error else MaterialTheme.colorScheme.onSurfaceVariant,
                    )
                )
                Box(
                    modifier = Modifier
                        .matchParentSize()
                        .clickable { 
                            showDatePicker = true
                            isDateTouched = true // Фиксируем, что пользователь нажал на выбор даты
                        }
                )
            }

            Spacer(modifier = Modifier.height(16.dp))

            Button(
                onClick = {
                    if (isFormValid) {
                        viewModel.addTrip(title = title, city = city, date = dateText)
                        onBack()
                    }
                },
                modifier = Modifier.fillMaxWidth(),
                enabled = isFormValid
            ) {
                Text("Сохранить", style = MaterialTheme.typography.titleMedium)
            }
        }
        
        if (showDatePicker) {
            DatePickerDialog(
                onDismissRequest = { showDatePicker = false },
                confirmButton = {
                    TextButton(onClick = {
                        val selectedDate = datePickerState.selectedDateMillis
                        if (selectedDate != null) {
                            dateText = convertMillisToDate(selectedDate)
                        }
                        showDatePicker = false
                    }) {
                        Text("ОК")
                    }
                },
                dismissButton = {
                    TextButton(onClick = { showDatePicker = false }) {
                        Text("Отмена")
                    }
                }
            ) {
                DatePicker(state = datePickerState)
            }
        }
    }
}

fun convertMillisToDate(millis: Long): String {
    val formatter = SimpleDateFormat("dd.MM.yyyy", Locale.getDefault())
    return formatter.format(Date(millis))
}
